# Project context

Notes for picking this project up again, by a person or by an AI assistant.
They record what the code and `README.md` do not: why things are the way
they are, what was tried, and what is planned. Keep them short and current;
delete what stops being true.

| File | What it holds |
|---|---|
| [state.md](state.md) | What is built, what is in progress, what is next |
| [decisions.md](decisions.md) | Design decisions and the reasons behind them |
| [direction.md](direction.md) | Where the project is meant to go beyond the current plan |
| [releasing.md](releasing.md) | How a version is tagged, built, signed and published |
| [testing.md](testing.md) | How to run it against real stores and a real kernel, and known pitfalls |

These notes are public. What must stay out of them (deployments, secrets,
unfixed weaknesses) is listed in [CLAUDE.md](../../CLAUDE.md).
